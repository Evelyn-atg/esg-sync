# OCR 抽样核对报告：哪些表格没有进入最终数字结果（2026-08-01）

> **这一步在 workflow 的位置**：发生在「GPU 表格 OCR → `numeric_extracts`」之间 —— 用 10 份随机抽样，核对 **OCR 检出的表格区域**（`chandra_ocr_2/<pdf>/<pdf>_ocr_output.json`）与**最终数字块**（`numeric_extracts/<pdf>/numeric_blocks.json`）之间的一致性，定位疑似未进入最终结果的表格。
> 全流程地图见 `ESG_Pipeline_Full_Workflow.md`；「能否准确去掉无数字表格」的结论见该文档 §4/§5。

## 1. 方法与结构性局限（为什么只能做到页码粒度）

匹配方法试了三层，逐层揭示了数据结构的限制：

| 版本 | 方法 | 结果 |
|---|---|---|
| v1 | 按页计数（页上表数 > 块数即标记） | **过度标记**：同页 2 表 1 块时无法区分哪张进了 |
| v2 | 用 OCR 表的 `table_block_id` 精确匹配块的 `source`/`content` | **失败**：全部样本 exact_hit=0 —— 块的 `source` 恒为 `"table_ocr"`，**不带任何表 id** |
| v3 | 内容分类（真表格/图表/其他）+ 页码级覆盖 | 当前结果（§2/§3），仍是页码粒度 |

**结构性结论**：OCR 缓存与 numeric 块之间**不存在显式关联**（无 id、无 bbox、`source` 是常量标签），因此**无法逐表证明"某张表是否被排除"**；且 numeric 块**按页聚合**（一个块可含整页多张表），页面级"表数 > 块数"也不等于丢表。

## 4. 结论

1. **无法逐表枚举"被排除的表格"**：块不携带表 id、按页聚合，这是当前数据结构的硬限制（`source="table_ocr"` 证实）。
2. **已证实的事实**：表格检测器把大量**图表/图片区域**检测为表并送入 GPU OCR（7 个疑似页预览为图表），它们不产生数字块属预期 —— 这解释了大部分"疑似缺失"。
3. **真表格疑似缺失**：B 类 14 个页面是真信号，建议人工抽查（对照 PDF 原文页）确认是否漏采。
4. **对"准确去掉无数字表格"的回答**：当前实现**做不到**（表格块不做数字过滤 + 无法审计），需 `ESG_Pipeline_Full_Workflow.md` §5 的三项改造。

**进一步精确化建议**：再做一层**内容级匹配** —— 统计每页 has_table 块 content 中 `<table>` 出现的次数，与该页表区域数对比；相等即全进、不等才真缺。该步可用脚本完成（当前 v3 未含）。
